# Step 09. 코드는 어떻게 발전했는가?

최종 코드만 보면 왜 현재 구조가 되었는지 알 수 없습니다. 이 문서는 10차부터 29차까지의 코드를 다섯 단계로 묶어 변화의 이유를 설명합니다.

| Phase | 버전 | 핵심 질문 | 결과 |
|---|---|---|---|
| 1. Baseline | 10차 | 기준 모델은 어디까지 가능한가? | `0.7412` |
| 2. Feature 탐색 | 11~15차 | 이전 행동과 구조 신호가 도움이 되는가? | 대부분 실패, 일부 신호 채택 |
| 3. 분석 인프라 | 15c~20차 | 오류와 메모리를 체계적으로 관리할 수 있는가? | 분석 체계 확립, `0.7456~0.7458` |
| 4. 복잡한 구조 | 21~27차 | Gating·Stacking·메타피처가 경계를 해결하는가? | 복잡도 증가, 27차 `0.7351` |
| 5. Noise-aware 전환 | 29차 | 모호한 표본의 영향을 줄일 수 있는가? | `0.7481~0.7499` |

## Phase 1 — 기준점 만들기

10차는 XLM-R, class-weighted loss, 최소 메타피처로 이후 실험의 기준을 만들었습니다. 이때부터 네 개 파일 탐색 클래스의 취약성이 관찰됐습니다.

## Phase 2 — Feature를 추가하면 해결될까?

직전 Action one-hot, 계층 분류, supervised contrastive loss, 규칙 기반 신호, pre-tokenization을 시도했습니다. 신호 일부는 유효했지만, 여러 변수를 동시에 바꾸거나 메모리 비용이 큰 구현은 롤백했습니다.

## Phase 3 — 점수보다 분석 도구

`errors_all.csv`, epoch 요약, Attention, Integrated Gradients, 메모리 진단, best-state 보존을 추가했습니다. 성능 향상은 작았지만 이후 가설을 데이터로 검증할 기반이 됐습니다.

## Phase 4 — 복잡한 구조의 한계

Re-ranking, 2-pass gating, Gradient Boosting stacking, 12-class 통합, 대규모 메타피처를 시험했습니다. 12-class `0.7785`는 클래스 수 감소로 인한 비교 불가능한 착시였고, 14-class로 복원했습니다.

## Phase 5 — 모두 맞히기에서 모호성을 다루기로

29차는 낮은 margin 표본을 모두 강하게 학습하는 대신 sample weight를 낮췄습니다. 27차 대비 약 `+0.008~0.009`의 개선을 확인했습니다. 단, prior model의 confidence를 다시 weight로 쓰는 순환성은 한계로 남겼습니다.

