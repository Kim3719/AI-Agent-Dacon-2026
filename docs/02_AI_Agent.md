# AI Agent 이해

## 목적

이번 대회의 예측 대상인 AI 코딩 에이전트의 작업 흐름과 action 클래스를 정리합니다.

## 이 문서는 무엇인가

모델이 예측해야 하는 14개 action이 실제 AI 코딩 에이전트 작업에서 어떤 의미를 갖는지 설명하는 문서입니다.

데이터를 보기 전에도 label의 의미를 팀원들이 같은 기준으로 이해하도록 만드는 것이 목적입니다. 향후 오류 분석을 하면서 “왜 이 샘플은 `read_file`이 아니라 `grep_search`인가?” 같은 기준도 이 문서에 보강합니다.

## 핵심 개념

모델은 사용자와 대화하며 작업 중인 AI 코딩 에이전트가 다음에 어떤 행동을 취해야 하는지 예측합니다. 각 action은 도구 사용 또는 응답 전략을 의미합니다.

## Action 클래스

| 클래스 | 의미 | 비고 |
| --- | --- | --- |
| `read_file` | 파일 읽기 | 파일 내용 확인 |
| `grep_search` | 패턴 검색 | 코드/문서 내 텍스트 검색 |
| `list_directory` | 디렉터리 목록 확인 | 작업공간 탐색 |
| `glob_pattern` | 파일 패턴 검색 | 파일 발견 |
| `edit_file` | 기존 파일 수정 | 직접 수정 |
| `write_file` | 새 파일 작성 | 새 산출물 생성 |
| `apply_patch` | diff 패치 적용 | 구조화된 코드 수정 |
| `run_bash` | 셸 명령 실행 | 일반 명령 실행 |
| `run_tests` | 테스트 실행 | 검증 |
| `lint_or_typecheck` | 린트/타입 검사 | 품질 확인 |
| `ask_user` | 사용자에게 질문 | 추가 정보 필요 |
| `plan_task` | 작업 계획 수립 | 작업 분해 |
| `web_search` | 웹 검색 | 외부 정보 확인 |
| `respond_only` | 도구 없이 응답 | 직접 답변 |

## 에이전트 의사결정 신호

- 현재 사용자 의도
- 작업공간 상태
- 이전 도구 호출 기록
- 최근 실패 또는 테스트 결과
- 남은 토큰 예산
- 사용자 선호 언어

## 분석 질문

- 어떤 프롬프트가 파일 읽기를 강하게 암시하는가?
- 어떤 히스토리 패턴 뒤에 테스트나 린트가 이어지는가?
- 토큰 예산이 낮을 때 직접 응답 비율이 높아지는가?
- 어떤 action 쌍이 자주 혼동되는가?
