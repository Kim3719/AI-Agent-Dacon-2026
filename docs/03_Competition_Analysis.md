# 대회 분석

## 요약

대회 규칙, 평가 방식, 제출 형식, 주요 제약사항을 추적하는 문서입니다.

## 이 문서는 무엇인가

대회 운영상 반드시 확인해야 하는 내용을 모아두는 문서입니다. 모델 성능과 별개로, 제출 형식이나 외부 데이터 규칙을 잘못 이해하면 실격 또는 재제출 문제가 생길 수 있으므로 대회 초반에 가장 먼저 채워야 합니다.

현재는 사용자가 제공한 대회 설명을 바탕으로 기본 구조만 정리했고, 공식 metric과 세부 규칙은 추가 확인이 필요합니다.

## 문제 유형

- 유형: 다중 클래스 분류
- 클래스 수: 14개
- 학습 데이터: 70,000개
- 공개 test 파일: 형식 확인용 5개 샘플
- 비공개 평가 데이터: 30,000개

## 데이터 파일

| 파일 | 목적 | 상태 |
| --- | --- | --- |
| `data/train.jsonl` | 학습 입력 데이터 | 외부 제공 |
| `data/train_labels.csv` | 학습 정답 라벨 | 외부 제공 |
| `data/test.jsonl` | 공개 형식 확인 샘플 | 외부 제공 |
| `data/sample_submission.csv` | 제출 양식 | 외부 제공 |
| `baseline_submit.zip` | 베이스라인 제출 예시 | 외부 제공 |

## 제출 형식

```csv
id,action
sample_id,respond_only
```

`action` 값은 14개 클래스명과 대소문자까지 정확히 일치해야 합니다.

## 리스크

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| Private test 분포 차이 | 리더보드 점수 하락 | 검증 split을 견고하게 설계 |
| 프롬프트 템플릿 과적합 | 일반화 성능 저하 | 세션 패턴별 오류 분석 |
| 클래스 불균형 | 소수 클래스 재현율 저하 | class weight 또는 sampling 검토 |
