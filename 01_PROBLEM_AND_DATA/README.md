# Step 01. 어떤 문제를 해결하려고 했는가?

## 어떤 문제가 있었는가

AI 코딩 에이전트의 대화와 작업 이력을 읽고 다음에 수행할 행동을 14개 클래스 중 하나로 예측해야 했습니다. 단순한 문장 분류와 달리 현재 요청뿐 아니라 이전 Action, 실행 결과, 열린 파일, 세션 상태가 다음 행동에 영향을 줄 수 있었습니다.

평가는 Macro-F1이므로 빈도가 높은 클래스를 잘 맞히는 것만으로는 충분하지 않았습니다. 모델 크기 1GB, 오프라인 실행, 제한된 추론시간을 고려해야 하는 코드 제출형 대회이기도 했습니다.

## 왜 이 접근을 선택했는가

처음부터 복잡한 구조를 만들기보다, 전체 History와 현재 Prompt를 하나의 텍스트로 직렬화하고 다국어 문장을 처리할 수 있는 사전학습 언어모델로 분류하는 접근을 선택했습니다.

## 어떻게 적용했는가

- 입력: 현재 Prompt, 과거 User 메시지, Action 이름·인자·결과, 세션 메타데이터
- 출력: 14개 다음 행동 중 하나
- 평가: Macro-F1과 클래스별 Precision/Recall/F1
- 검증 단위: 초기 Random split에서 이후 Session group split으로 교정
- 배포 조건: 모델 크기, 오프라인 패키지, 실행시간을 모델 선택에 포함

## 결과가 어땠는가

초기 제출은 `0.6XXX`였으며, 이후 확인된 XLM-R 연구 Baseline은 Validation Macro-F1 `0.7412`였습니다. 첫 결과는 모델 선택만이 아니라 입력 구성과 검증 설계가 중요하다는 출발점이 되었습니다.

## 왜 성공하거나 실패했는가

텍스트 Backbone은 전체적인 의미를 포착했지만, 비슷한 파일 탐색 행동은 표면적인 문장만으로 구분하기 어려웠습니다. 또한 동일 세션의 표본들이 강하게 연관되어 있어 독립 표본을 가정한 Random split은 실제 일반화 성능을 과대평가할 수 있었습니다.

## 다음에는 어떻게 활용할 것인가

후속 AI Agent 연구에서는 처음부터 행동 정의, 세션 구조, 평가 단위, 배포 제약을 함께 설계합니다. 모델을 선택하기 전에 “새로운 세션에도 일반화해야 하는가?”를 먼저 명시합니다.
